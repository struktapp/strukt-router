# Native `$_SESSION` store

## What changed

- Added `Strukt\Http\Session\Native`, a concrete session store that reads and
  writes PHP's native `$_SESSION` superglobal. It extends `Strukt\Session`, so it
  still satisfies `Strukt\Contract\Http\SessionInterface`.
- Values **and** flashes persist. Flashes are stored under a reserved key and are
  consumed as they are read, so they survive a redirect and last one request;
  `all()` excludes them.
- Under a web SAPI the constructor starts the session (`@session_start()`); under
  the CLI it does not, so tests and console scripts see no session side effects.
- Placed beside the other `Strukt\Http\*` classes, mirroring strukt1's
  `strukt-router/src/Strukt/Http/Session/Native.php`.

## Why

`Strukt\Session` is a by-value, in-memory store, so `new Session($_SESSION)`
silently discards every write at the end of the request. Real applications had
to subclass it in application code (the skeleton carried a `Web\NativeSession`).
Shipping the native store in the package removes that boilerplate and matches the
strukt1 layout.

## Documentation

- `docs/http-layer.md`: new "Session store" section comparing `Strukt\Session`
  and `Strukt\Http\Session\Native`.
- `docs/authentication.md`: the factory example binds `Native` instead of the
  `new Session($_SESSION)` footgun; the persistence section explains the change.

## Tests

- `tests/Unit/NativeSessionTest.php` (7 tests): value read/write against
  `$_SESSION`; reading directly written values; remove/clear; flash persistence
  across instances and consumption on read; `pullFlash()`; `all()` excluding
  flashes; and no session start under the CLI.

## Public API impact

- New class `Strukt\Http\Session\Native`. No existing signatures change.
