# Cache-backed session store

## What changed

- Added `Strukt\Http\Session\Cache`, a concrete session store that persists
  values **and** flashes through any `Strukt\Contract\CacheDriverInterface`
  driver — memcached, the filesystem, or memory. It extends `Strukt\Session`, so
  it still satisfies `Strukt\Contract\Http\SessionInterface` and needs no router
  changes.
- Values and flashes are written together under one reserved driver key
  (`session`), so session keys that contain dots (`user.id`) are never read as
  cache paths and `all()` keeps the same shape as the in-memory store.
- Mutations (`set`, `remove`, `clear`, `flash`, `getFlash`, `pullFlash`) write
  through to the driver and call `save()`; reads are inherited.
- The driver instance doubles as the client key: a driver is a namespace, so
  binding `memc('sess_' . $sid)` gives every client an isolated session.
- `strukt/cache` is added as a **dev** dependency (with path repositories for
  `strukt/cache` and its `strukt/fs` dependency) so the suite can exercise it.
  It is not pulled into a production install, which keeps the package free of
  required PHP extensions.

## Why

`Strukt\Http\Session\Native` persists in `$_SESSION`, which is bound to one PHP
process. Applications that run behind a load balancer or share state across
workers need a session backend they can reach from any process. The `strukt4`
cache package already ships a memcached driver, so a thin adapter over its
driver contract gives the router that backend without a new dependency for
callers who do not need it. The work mirrors strukt1's `Http\Session` namespace.

## Documentation

- `docs/http-layer.md`: the "Session store" table now lists
  `Strukt\Http\Session\Cache` with a binding example and the namespace-as-key
  note.
- `docs/authentication.md`: the persistence section explains the shared-store
  use case and shows the `memc('sess')` binding.
- `docs/installation.md`: records that the cache store is optional and needs
  `strukt/cache`, `ext-zip`, and — for the memcached driver — `ext-memcached`.
- `README.md`: the auth example now binds `Strukt\Http\Session\Native` instead
  of the stale `new Strukt\Session($_SESSION)`; the "HTTP layer" section lists
  both session stores with a binding snippet.

## Tests

- `tests/Unit/CacheSessionTest.php` (10 tests): values persisting across
  instances; pre-seeded namespaces; dotted session keys staying intact;
  remove/clear with flashes retained; flash persistence and consumption;
  `pullFlash()`; `all()` excluding flashes; client isolation by namespace; a
  filesystem round trip; and a memcached round trip that skips when the
  extension or server is unavailable.

## Public API impact

- New class `Strukt\Http\Session\Cache`. No existing signatures change.
- The router still requires no PHP extensions; the cache store is opt-in.
