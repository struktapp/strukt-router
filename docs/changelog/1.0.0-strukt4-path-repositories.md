# 1.0.0 — Strukt4 path repositories

**Date:** 2026-10-14

**Changed**

- `composer.json`: the `strukt/form` path repository now points at
  `../../strukt4/form` instead of the stale `../../strukt3/form`.
- `composer.json`: added a `strukt/rules` path repository
  (`../../strukt4/rules`), which `strukt4/form` requires; without it the
  corrected `form` dependency could not resolve.
- Documentation and example comments updated from `strukt3/*` to `strukt4/*`:
  `README.md`, `docs/architecture.md`, `docs/installation.md`,
  `docs/http-layer.md`, `docs/api-reference.md`, `examples/11-helpers.php`.
- `tests/Pest.php`: the route-lister helper now runs `bin/routes`, matching the
  binary declared in `composer.json` (was the non-existent
  `bin/strukt-routes`).

**Why**

- The router was still resolving `strukt/form` from the strukt3 tree, so
  `vendor/` held strukt3-era code. Correcting the path also required declaring
  the `rules` repository that the strukt4 `form` package pulls in.

**Documentation**

- `README.md`, `docs/architecture.md`, `docs/installation.md`,
  `docs/http-layer.md`, `docs/api-reference.md`: dependency and contract
  references now name the strukt4 packages.

**Tests**

- `tests/Unit/RouteListerTest.php`: the binary subprocess now runs; previously
  the helper pointed at a missing `bin/strukt-routes`. 79 tests pass.

**Public API impact**

- None.
